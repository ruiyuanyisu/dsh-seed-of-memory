# 审查包 24 个脚本：搬过来之后的差异清单

跑法：`node test\review\run.mjs`（一个文件一个进程，末了汇总）。
一个原脚本对应一个文件（`01-…` 到 `24-…`），问的是同一件事，调用的是 1.5.0 的真实接口。

## 我故意做得和他不一样的（按我的语义断言，不是漏做）

| 他的做法 | 我的做法 | 为什么 |
| --- | --- | --- |
| `mood_scoped` 表，心情按会话分 | 心情只有一份（mood / qing_state），分人的是 emotions.slot 和 tones.slot | 心情是「我」一个人的身体。A 骂我难受了，我对 B 也不会忽然没事——分人的是「最近那一下」和连着骂的计数。（14、20、22） |
| `personKeyOf` / `peerKeyOf`：群按人切 `group:gid@uid` | 群档按整群 `group:<群号>`，谁说的写进正文（`lastSpeaker`） | 群是一个场子，记忆本来就该整群共享；一个人一个档会在群里立刻碎片化。谁说的靠正文那句提醒模型，不靠拆档。（02、04、18） |
| `qing.use(slot)` 切账本 / `snapshotOf(slot)` | `qing.snapshot(now, slot)`，slot 只滤 events/tones | 没有「切账本」这个概念——身体只有一个，不需要切。（20、22） |
| `shouanren_patches` 标记表 + 版本号推到 17 | `user_version = Math.max(...)` + 迁移每轮自愈（缺列补列） | 两条路都能解「版本号撞车」，自愈还顺便修好「表在列不在」的坏库；不用多一张表。（07 验 `user_version` 与五个索引） |
| 注入卡片十二段各自 try（静态检查） | 一样，各段各自兜底 + 最外层留固定底色 | 这条本来就是对的，我照做了；13 静态验结构。（13） |
| `stop()` 时记 `drop:` 日志 | `stop()` 时把没发出去的那句记进会话账本 + resolve 掉 waiter | 只记日志仍然会丢那句话；记进账本，下次还能看见。（24） |

## 我照着他的思路补的

- `emotions.slot` / `affects.slot` / `captures.slot` / `beliefs.scope`：整条链（store → capture → affect → qing → index → channel → compat）都带上了。
- 消息 `source` 带身份：`platform / scope / peerId / userId / senderName / groupId / fromMe`（channel `#sourceFor`）。（23）
- 图片路径只认图片后缀，先判后读，拦下来记一条日志。（11）
- 指令（「放她进来」）落盘成 `qq-orders.json`，重启后安全门还认得。（16、17）
- 群聊复盘不冠「老大」：`recap(key, limit, who)`。（09）
- 整理记忆用 SAVEPOINT，外层事务开着也不炸。（15）

## 1.5.1 又变了的三处（审查包第五轮之后）

- **老桶 qq 只剩「当面」看得见**：1.5.0 那会儿任何 qq 侧都读得到它，等于升级前所有人的话人人可读；
  现在 isibleScopes 里 qq:<号> / group:<群号> 只有 [shared, 自己]。数据一条没删、没挪。
  所以 19-per-user 的断言跟着改成 ['shared', 'qq:10001']。
- **gui 能接管 shared**：同键撞上 shared 时改的是那一条，而且仍留在 shared（不降级）。
  ownScopes('gui') 因此是 ['gui', 'shared']。
- **QQ 会话 id 带号**：seedqq-<hash16>-q<号> / -g<群号>，解析在 lib/scope.js 的 scopeOfSessionId。
  守岸人第四轮说的「重启后认不出会话是谁的」就是靠它和账本反查一起补的。
